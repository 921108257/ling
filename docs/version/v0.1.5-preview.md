# v0.1.5 预览版：可观测性与热路径证据

> 状态：规划，未开始实现。基线为 0.1.4 发布后的 `main`；条目编号引自 [baseline-0.1.3.md](baseline-0.1.3.md)，索引见 [README.md](README.md)。

## 主题与目标

0.1.4 收敛缺陷，0.1.5 回答另一个问题：时间花在哪里。阶段 7 的测量对应 0.1.2 之前的源码，0.1.3 又新增了内置更新与分层帮助；当时的瓶颈判断主要来自源码路径，`perf_event_paranoid=4` 拒绝了性能计数器，没有剖析数据。本版先重建可复现的测量与运行时指标，再只对数据支持的热点动手。

1. 在干净工作区重测基线，覆盖阶段 7 的 18 类场景（M-01、M-07）。
2. 补齐运行时指标：执行许可等待、fsync 时延、维护循环、连接拒绝等。
3. 分解 TCP 路径的固定成本，对照 `TCP_NODELAY`（P-03、P-04）。
4. 校准受管内存核算与 RSS（P-07、P-08）。
5. 量化订阅轮询成本（P-02）。
6. 加入属性测试、模型对照测试与持续模糊（M-02、M-08、E-04）。

## 不做的事

- 不改变协议 v1、Journal v1、命令语义、错误码与配置键，不新增命令。
- 不预设倍数；没有提升同样是有效结果，写入 testing.md。
- 没有剖析数据，不引入自定义分配器、无锁索引或时间轮（见 AGENTS.md 的「实现方法」）。
- 短测量不是稳态容量或生产尾延迟承诺。

## 分级与门槛

P0：工作包 1、2。P1：3、4、5。P2：6、7。发布门槛：P0 完成；每项性能改动都有同法、同环境、改动前后各三次以上的原始数据；原子性、事件提交与资源上限的契约测试通过；未执行项在发行说明中列出。

## 工作包 2：运行时可观测性（P0，状态：未开始）

新增指标只用固定低基数标签，不以 Key、Value、组名或地址作标签。Prometheus 沿用现有 `linger_` 前缀，兼容名称的处置见 DEC-08。每项新增须同步 config.md、commands.md 的 INFO 与指标说明及共享用例。

- 执行许可：等待时延直方图、当前占用与排队数，用于判断 P-02、P-04。
- Journal：fsync 时延直方图、事务字节分布、压缩次数与耗时，用于判断 P-05。
- 维护循环：循环次数、回收条目数、因许可忙而推迟的次数，用于复测 P-01。
- 连接：接受错误、因连接上限拒绝、首帧超时关闭、AUTH 失败；0.1.4 引入的内部计数在此对外暴露，不重复定义。
- 订阅：订阅者数量、轮询次数与空轮询占比。
- 进程：Linux 上的 RSS 与 CPU 时间，使受管字节与 RSS 能并排对照（P-07）。
- 慢命令日志需要新的配置键，列为候选，不在本版承诺。

验收：新增指标的名称、类型、单位写入文档并有契约测试；开启指标前后用工作包 1 的 GET、SET、混合场景比较吞吐，记录开销。开销超过噪声时改为采样，或默认关闭。

## 工作包 3：TCP 路径成本分解（P1，状态：未开始）

目的：回答「TCP GET 的 P50 为 172 μs、引擎直调为 1 μs，差在哪里」。同一负载（64 B Bytes，GET，4 个闭环客户端，流水线深度 1，1000 个预填充 Key），逐层剥离后测量：引擎直调、仅编解码、回环 echo（同样的帧）、完整路径。

| 任务 | 来源 | 做法 | 验收 |
|---|---|---|---|
| 3.1 NODELAY 对照 | P-03 | 仅测量构建中提供服务端接受流设置 TCP_NODELAY 的开关，A/B 各三次以上，含 Reliable 与订阅场景；同时核查 Java SDK 的套接字选项（本次审查未读），三种 SDK 的行为写进 sdk.md | 收益落在噪声内也要记录，并说明最终是否显式设置 |
| 3.2 许可与阻塞池 | P-04 | 单独测量「取得许可 + `spawn_blocking` + 返回」的固定成本，与引擎执行时间并列。候选优化必须保持「网络等待不持有引擎锁」与有界执行许可；在异步线程里直接持有 `std` 互斥锁会阻塞运行时，不属于候选。任何并发模型改动先写进 architecture.md，再实现 | 候选方案在 18 类场景中至少 TCP GET、SET、混合三类，改动前后各三次以上，P99、P99.9 与吞吐并列报告 |
| 3.3 回归 | P-04 | 优化合入前运行引擎契约、`ownership_tests`、`crates/server/tests` 与 `tests/sdk_contracts.py` | 无原子性、屏障、关闭语义回归 |

不做：不预设「减少一次线程切换」是方向；若剖析显示成本主要在别处，本包只留下测量结论。

## 风险与未决

- 虚拟机同机回环的方差较大（阶段 7 记录 Fast 无消费者三次约 11,764 至 17,071 请求/秒）。结论只用于相对比较，独立压测机可用后复测（M-01）。
- 度量本身可能改变被测路径。新增指标按工作包 2 的验收评估开销，超过噪声则采样或默认关闭。
- 性能计数器不可用时，剖析依赖时间戳埋点等手段，结论写明限制；不引入需要不稳定特性或新运行时依赖的调试组件。
- 多个优化候选可能相互影响。每次只合入一项变更并逐项复测，不把多项改动合并成一次对比。
- DEC-09 未决之前，所有数据都只是本机验收级别，不写成目标环境结果。
