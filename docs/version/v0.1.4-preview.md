# v0.1.4 预览版：基线收敛

> 状态：本次范围已验收，2026-11-17 已发布 v0.1.4 Preview。候选 `e60427e` 已通过 Actions `44056119224`；标签 `v0.1.4`（`b073054`）通过发布流水线 `44057670375`。未完成的 P1/P2 按下文顺延。基线 0.1.3（`53a9f46`）。条目编号（R-、S-、P-、E-、D-、M-）引自 [baseline-0.1.3.md](baseline-0.1.3.md)，证据与影响见该文。索引见 [README.md](README.md)。

## 主题与目标

0.1.4 不新增数据库能力，不改变协议字节、类型标签、Journal 磁盘格式与命令语义。它把 0.1.3 审查中有代码证据的缺陷收敛掉，让文档与实际一致，补齐公开发行需要的仓库治理，并为 0.1.5 的性能工作准备可信的测量起点。

1. 服务在瞬时错误和单连接故障下不整体退出（R-01 至 R-04）。
2. 认证使用常量时间比较并限制在线猜测，明文暴露面有启动期告警（S-01、S-04）。
3. 空闲服务不再以 1 ms 周期空转（P-01），前后有同法实测。
4. 契约文档不再包含过期的版本号、状态说明与数字（D-01 至 D-04、D-07）。
5. 仓库具备许可证、安全披露渠道、变更记录与依赖审计（E-01、E-02、S-06）。
6. 发行与 CI 对关键输入做摘要校验，Windows 覆盖核心引擎契约（S-03、E-03、E-04）。

## 不做的事

- 不修改协议版本、帧头、Value 标签、错误码注册表和 Journal 格式，不新增命令，不新增配置键。
- 不做以吞吐为目标的优化；接入预算是稳健性修复。P-01 只处理空转，以 CPU 时间和回收延迟分布验收。
- 不触碰 [architecture.md](../architecture.md) 已排除的范围，如缓存持久化、集群、Redis 兼容。

## 分级与发布门槛

P0 必须完成并有实际运行的验证记录；P1 计划完成，可在发布前以书面理由顺延；P2 有余量才做，默认顺延到 0.1.5。

发布门槛：全部 P0 完成；`cargo fmt --all -- --check`、`cargo test --workspace`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo doc --workspace --no-deps`（`RUSTDOCFLAGS` 取 `-D warnings`）、`python3 tests/sdk_contracts.py` 在 Linux 或 macOS 上实际执行通过；Windows 子集在 CI 通过；未执行的项目在发行说明中逐项列出。
