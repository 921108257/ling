## 编号、状态与证据

条目按类别编号：R 稳健性、S 安全与供应链、P 性能、E 工程与发行、D 文档、C 客户端、F 功能缺失、M 测量与验收。编号一经使用不重用，被推迟的条目保留原编号。证据分为实测（本轮实际观察）、代码（已定位实现）、文档（规范或历史记录）、推断（需实验确认）。影响级别 L1 至 L4 的定义见基线文档。

版本文档中的工作包以「未开始 / 进行中 / 已完成 / 已推迟」标注状态。完成时附实际运行的验证命令与结果摘要，不把建议命令写成已通过。没有测量，不写「更快」「零丢失」「生产可用」。

## 排期规则

1. 每版有明确主题。P0 全部完成才发布，P1 可书面顺延，P2 默认顺延。
2. 优化类条目先测量、再改动、后复测：先记录基线，再做单项变更；改动前后使用同一脚本与同一环境，至少三次独立运行并保留原始数据；原子性、事件提交、资源上限与尾延迟都要复测。不预设倍数。
3. 版本号与协议版本、Journal 格式版本相互独立。0.1.x 与 0.2.0 不改变协议 v1 与 Journal v1；若某条目必须改变，在该版本文档中单列并写明升级与回退方式。
4. 版本过大时拆分，不降低验收标准。
