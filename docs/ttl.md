# TTL 与 Key 生命周期

> 状态：设计规范草案 v0.3，尚未实现。范围以 [architecture.md](architecture.md) 为准；命令返回值见 [commands.md](commands.md)。

## 范围与时间单位

首个稳定版支持相对到期、绝对到期和移除 TTL，精度为毫秒。访问不会自动续期；Idle TTL、Sliding TTL 和后台数据恢复不属于此版本。

| 操作 | 单位与含义 |
|------|------------|
| `SET ... EX seconds`、`EXPIRE` | 从服务端执行该操作的时间起计算，秒乘以 1,000，检查溢出 |
| `SET ... PX milliseconds`、`PEXPIRE` | 从执行时间起计算的毫秒间隔 |
| `SET ... EXAT timestamp`、`EXPIREAT` | Unix 秒时间戳 |
| `SET ... PXAT timestamp`、`PEXPIREAT` | Unix 毫秒时间戳 |
| `PERSIST` | 移除现有 TTL |
| `TTL` / `PTTL` | 剩余秒数 / 毫秒数 |
| `EXPIRETIME` / `PEXPIRETIME` | 到期 Unix 秒数 / 毫秒数 |

`SET` 的四种到期选项互斥，`NX` 与 `XX` 互斥。`SET` 的相对间隔必须大于零，绝对时间必须晚于本次执行时间；无效值返回错误且不修改 Key。`EXPIRE` / `PEXPIRE` 的非正间隔，以及绝对到期命令中的过去时间，对存在的 Key 执行立即过期。

`TTL`、`PTTL`、`EXPIRETIME`、`PEXPIRETIME` 均以 `-1` 表示没有 TTL、`-2` 表示不存在或已经过期。秒值向下取整：剩余不足一秒但尚未到期时 `TTL` 为 `0`。所有计算使用检查算术，不能因时间溢出使 Key 永不过期。

## 可见性边界

每次服务端操作在获得有关 Shard 的执行权后读取一次时间，使用该时间判断命令涉及的 Key。满足 `now >= deadline` 的 Key 对该操作已不存在，即使时间轮还没有处理它。

所有入口遵守此规则，包括读取、条件写入、数值修改、集合命令、扫描、复制和数据库管理操作。`DBSIZE` 返回该操作观察时的活跃 Key 数，不能直接返回尚含过期条目的索引长度。

过期与不存在具有相同的对外查找语义：`GET` 返回 `ERR_KEY_NOT_FOUND`；`EXISTS` 不计数；`SET NX` 可以创建；`SET XX` 不写入。已到期条目不能被 `PERSIST` 或再次 `EXPIRE` 复活。

原始缓存条目可以暂时保留在内存中，仅供过期事件记账和回收使用，不允许作为正常 Value 返回。时间轮调度的延迟不会延长数据的逻辑有效期。

## 身份、修订与旧任务

Key 的一次创建分配唯一 generation：`(process_epoch: u128, creation_counter: u64)`。进程启动时创建新的 epoch；创建计数在进程内全局分配，跨数据库和 Shard 不重复。删除后重建、移动或复制到新生命周期均分配新身份，计数耗尽必须停止分配，不能回绕。线上对应字段名仍为 epoch / counter。

新 generation 的 revision 为 1。同一 generation 内一次成功命令改变值、TTL 或两者时，`revision: u64` 递增一次；完全没有改变状态的操作不递增。终结事件携带最后 revision；修订号不能回绕。generation 标识生命周期，revision 标识该生命周期内的状态版本。

过期任务至少携带数据库、Shard、Key、generation、revision 和 deadline。执行前必须同时满足：

```text
entry.generation == task.generation
entry.revision == task.revision
entry.deadline == task.deadline
now >= entry.deadline
```

任一条件不成立，任务已经失效，直接丢弃。续期、移除 TTL、值变更、删除和重建均不会被旧任务误删。值变更保留 TTL 时，也必须为新 revision 保留有效的调度任务。

## 提交、事件与回收

一次自然过期最多产生一条原始 `KEY_EXPIRED` 事件；至少一次投递可以让同一 `event_id` 被消费者多次收到。事件发生的具体时间和可恢复边界见 [events.md](events.md)。

```text
期限到达
  → 逻辑不可见
  → 在 Shard 执行权内确认 generation / revision / deadline
  → 建立过期记账记录
  → Reliable：Journal 提交并完成 fsync
  → 发布 KEY_EXPIRED
  → 移除条目并回收内存
```

Fast 模式在有界内存事件队列接受记账后即可回收；队列溢出可以丢失通知，但必须记录丢弃指标。事件禁用时直接回收，不生成通知。

Reliable 模式不能先回收唯一的待记账信息再异步补写 Journal。写盘失败或达到 Journal 容量上限时，条目继续逻辑不可见，保留待记账状态，并拒绝受影响 Shard 的新写入。读取仍正常执行 TTL 过滤；运维需处理磁盘或容量问题后才能恢复写入。

这不承诺过期通知的最大延迟，也不承诺进程崩溃后恢复尚未提交的过期记录。可靠范围是已经 fsync 提交的事件，而不是所有曾经驻留内存的 Key。

## 与其他变更的关系

| 操作 | TTL 行为 |
|------|----------|
| `SET` / `GETSET` / `MSET` 替换值 | 未显式指定到期时移除旧 TTL；`SET` 按其到期参数设置新期限 |
| 数值操作、`APPEND`、集合局部修改 | 保留原 TTL，不自动续期 |
| `PERSIST` | Key 存在且有 TTL 才改变状态 |
| `RENAME` / `MOVE` | 保留来源期限；目标按新的存储位置重新调度 |
| `COPY` | 复制当前值及同一绝对期限，不以复制时刻重新计算间隔 |
| 覆盖目标 Key | 按相应命令的 TTL 规则替换，不能遗留目标旧任务 |
| 集合修改后变空 | 保留空集合及原 TTL；不会隐式删除顶级 Key |

成功值变更产生 `KEY_CREATED` 或 `KEY_UPDATED`；显式期限变更产生 `KEY_TTL_CHANGED`。一次值替换同时改变 TTL 时，必须在同一提交中先产生值事件再产生 TTL 事件；值相同而仅 TTL 改变时只产生 TTL 事件。初次创建的 TTL 属于创建状态，不额外产生 TTL 事件。

立即过期的 `EXPIRE` 系列操作产生 `KEY_EXPIRED`，不再产生中间 `KEY_TTL_CHANGED`。`DEL` 产生 `KEY_DELETED`；内存淘汰产生 `KEY_EVICTED`。已经逻辑过期的条目只归为过期，不能被随后 `DEL` 或淘汰改记为另一删除原因。

写入同名已过期 Key 前，先完成旧 generation 的过期记账，再创建新 generation。Reliable 下两个变化可以包含在同一 Journal 原子事务中；失败时不得发布新值。条件判断仍基于逻辑可见性，不把待回收条目当作存在。

## 时钟与调度

相对 TTL 在执行时转换为期限，并使用单调时钟计时，避免系统时钟回拨延长间隔。绝对 TTL 根据服务端当次观察的 Unix 时间换算为单调期限，之后不随时钟校正重算；保留原 Unix 期限用于查询。

相对 TTL 的查询期限记录为接受时 Unix 时间加间隔；墙钟校正后，EXPIRETIME 与当前 Unix 时间之差不保证等于 PTTL。COPY、MOVE、RENAME、SWAPDB 同时保留原单调期限与查询期限，不重新按墙钟换算。

服务器时钟是否准确由部署环境保证。客户端不能用自己的本地时间覆盖服务端判断。无缓存数据恢复的首个版本无需跨重启恢复单调时钟期限。

时间轮按 Shard 维护，仅负责尽快定位可回收条目。实现可以先采用简单堆或其他可验证结构，再依据数据证明是否需要分层时间轮。调度粒度与逻辑过期精度分离，不能用“轮子尚未转到”解释读取到过期值。

调度器每轮应有工作量预算，防止大量同刻到期 Key 长时间占用 Shard；无论预算多少，读路径仍检查期限。续期产生的旧任务需要有界清理，避免高频续期导致队列无界增长。

## 重启与异常

首个稳定版不恢复缓存值和 TTL。启动时缓存为空，Journal 中已经提交的事件和命名组状态独立恢复；不为冷启动消失的 Key 合成删除或过期事件。

服务器停止期间到期、到期但未完成 Journal 提交，以及最后一次写入后直接崩溃的内存条目，均不承诺产生可恢复的过期通知。不能将此服务当作可靠定时任务队列。

优雅关闭先停止接受新写入，再处理已接受的变更和可完成的 Journal 提交。关闭超时允许退出，但只能把已经 fsync 的记录算作已提交。

## 必需验证

- 在到期前、恰好到期、到期后读取；时间轮故意停顿时也不能读到过期值。
- 秒与毫秒换算、绝对期限、零间隔、过去时间、算术溢出和查询哨兵值。
- 续期、`PERSIST`、保留 TTL 的值修改、删除重建，旧任务不能影响新状态。
- 过期与 `SET NX`、`SET XX`、删除、复制和扫描竞争时，结果满足统一可见性规则。
- 单调时钟与系统时钟校正、大量同刻到期、高频续期的内存及调度预算。
- Journal 提交前后崩溃、写盘失败、恢复重试，确认无重复原始过期事件且不提前回收。
